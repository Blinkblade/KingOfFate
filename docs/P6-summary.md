## 1. P6 要回答的问题

> 我们能不能用**正式美术**做出一个可玩的角色，而且不破坏 P1–P5 建起来的架构与证据链？

答案：能。角色 `game/chars/archer/`（Archer / EMIYA）可玩、可校验、可实测，
状态机/取消链/气账仍是 P1–P5 的那套，引擎仍未改动。

## 2. 做了什么

### 2.1 工具链（支撑换装）

| 工具 | 能力 | 验证 |
| --- | --- | --- |
| `sffpack` | SFF **v1 → v2** 转码 + 按映射表重编号 | 写出后回读逐像素比对 |
| `sffctl` | SFF v1/v2 读取、导出、拼图 | 与引擎解码器逐字节对照 |
| `sndctl` | SND 读取（155 音效 / 347 秒） | 逐条解析 WAV 头 |
| `anim_strip` | 把一个动作渲染成逐帧动作条（供目检） | — |
| `validate_character` | 角色级校验 | PASS |

新增能力：`sffpack --force-palette`（源包部分精灵指向调试色板）、
`AIR_NO_HURTBOX` 在"带攻击框但无受击框"时升级为 **WARNING**（原来是 INFO，
因此掩盖过一次真实缺陷）。

### 2.2 角色：美术

- 素材：**aka65535 / Sho 的 Nameless_Archer**（1803 精灵 / 423 动作，站立 162×249，
  6 套调色板，21 MB 音效含语音）。旧的 kuri 版保留为降级退路。
- `archer.sff` 355 精灵，由 `asset_map.csv`（355 行，0 未解析）转码生成。
- 两次关键发现：
  ① 源包部分精灵指向**调试色板** → 用 `--force-palette 0` 统一到正确色板
  ② 源包部分"动作"其实是**斩击特效帧**（高度只有人物的 55%）→ 建立规则：
     **映射前必须验证源动画是人物帧（最大精灵高 ≥150px）**

### 2.3 角色：判定与时序

- 攻击框：**直接取 kuri 为这套画面调好的形状**（`×(1/0.48)` 抵消引擎缩放）
- 受击框：`Clsn2Default` 覆盖整段（逐帧框只作用于紧邻元素）
- 时序：**三段化**（起手 / 判定 / 收招），每招都有 **4~15 tick 的可确反收招**
- 超必杀**保持长**（Super 40 / UBW 198）—— 稀有的"大反馈"，值得等待

**关键修正**：审计发现原本 12 个普通技的**收招 = 0**（攻击框开到动画结束），
等于没有惩罚层。已全部修好。

### 2.4 角色：操作（按新总纲）

```
只用 A / S / Z / X  → 不耗气的普通招式（12 个）
带 C                → 300~400 气的中型技能（4 个）
带 D                → 600~800 气的大型技能（3 个）
C + D               → 2000 气的终极技（无限剑制）
```

**没有任何搓招。** 只改了 `archer.cmd`（命令定义）与 `command.zss`（路由顺序），
**状态机一行没动**——这正是总纲 §5 预判的低工作量。

实测（注入真实按键 + F3 满气，读调试覆盖层）：
`C`→1000、`↓C`→1150、`→C`→1100、`←C`→1200、`D`→3000、`→D`→1300、`↓D`→1400、`C+D`→3100。

### 2.5 画面知识转移（本阶段最重要的方法论）

负责人提出"为什么不直接复用 kuri 的角色"，由此确立：

| 类别 | 例子 | 决策 |
| --- | --- | --- |
| **画面知识**（只对这套画成立） | 判定框形状、轴心、每招音效、投射物偏移 | ✅ 搬 |
| **战斗框架**（对这个游戏成立） | 状态编号、取消链、气账、AI、硬直约定 | ❌ 不搬 |

详见 [`P6-art-knowledge-transfer-plan.md`](P6-art-knowledge-transfer-plan.md)。

## 4. 过程中的两次自己造成的错误（记在这里防重演）

1. **转移判定框时把受击框整段丢掉** → 13 个攻击动作"无敌"。
   成因：脚本只保留了 Clsn1 + 元素行。**校验器没报**（该类问题当时是 INFO）。
   对策：① 该类问题升级为 WARNING ② 改 AIR 必须从干净版重跑脚本
2. **转移后又叠加了一次脚本** → 这次没出事，但同类风险仍在。
   对策：写进流程改进。
