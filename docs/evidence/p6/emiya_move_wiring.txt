## 1. 静态接线：72 条指令里 37 条有效、13 条是死的

方法：解析 `emiya.cmd` 的 72 个 `[Command]` 定义，再在 `emiya.cmd` + 5 个 `.cns`
里查找每条指令是否被 `[State -1]` 路由引用（该角色的命令路由写在 **.cmd 文件**里，
不在 .cns —— 第一次只扫 .cns 时误判为"几乎全死"，这是本次的教训）。

**有效（37 条）**

```text
普通技      x→200/260/400/600   y→220/262/420/620   z→250/264/440/640
            a→210/261/410/610   b→230/263/430/630
特殊技      tokusyu→240   nage→800/850   nage_b→800/850   tuika→852
必杀        trace_P→1000  trace_K→1001  trace_S→1002  hassya→1005/1011/1021/1031
            taikuu_S→1050  taikuu_HS→1051  yumi_S→1101/1150  yumi_HS→1100/1102
            kakato→1200  kusari→1300
超必杀/其它 UBW→3300/3301  UBW_S→3320  UBW_R→3500  UBWX→3900
            RO-→255/3700/3701  DC→3400  karado→1350/3000
            Combo_Rash→3100  AIR→3200（仅取消，见 §3）  BREAK→255/1050
移动/系统   FF→8/100  BB→9/105  JC→45  RG/C_RG→10  holdup→40  holddown→400/410/420/430/440
```

**死指令（13 条，定义为指令但没有任何状态引用它们 → 按了没反应）**

```text
c            ← 重脚按钮本身没接线（意味着 F+c / B+c 投技、66+c 都发不出来）
down_a  down_b        ← 倒地攻击
recovery recovery2 recovery3 recovery4   ← 空中受身
holdx  holdy  holdupa  holddowna          ← 多余的按住变体
jump         ← 大跳（~D,$U；普通跳走引擎内建）
GX           ← 秘技（B,B,F,F,B,F,B）
```

> 对 P6 的意义：这些是**素材来源角色**的完成度问题，不是我们的素材/管线问题。
> 我们的 `archer` 自己写命令层（Fighter B 骨架），不受影响；但要知道
> **这套精灵里没有"重脚 c"和"受身"对应的可用表现**，P6 若要这两项需自绘补充。

## 3. 注入装置的两条硬性经验（写给下一个窗口）

1. **长指令（41236 / 236236）与双击类（`↓↓`、`→→`、`←←`）对"相位间是否释放"的要求相反**：
   - 长指令：松键与下一次按键必须落在**同一帧**（`-SettleSec 0` + 每方向 0.03 s），
     否则中间的中性帧会切断指令序列 → 永远不匹配（实测：settle 0.02 s 就失败）。
   - 双击类：**必须留一个中性帧**（settle ≈ 0.07 s），否则引擎只看到一次按下。
2. **组合键（如 `/$F + c`）必须把方向与按钮放在同一个相位里同时按住**，
   分相位（先方向后按钮）不可能匹配。
3. F3 = `powMax(1); powMax(2)`，可注入 → 超必杀不需要先打中人即可测试（实测 POW 变 3000）。
4. OCR 速度：整图约 3.6 s/张；先裁到**底部 80 行**再读约 0.5 s/张（已在
   `read_move_evidence.py` 内置）。长 OCR 任务要分批（每批 ≤3 招），否则会被工具超时杀掉。

## 4. 结论（给 P6 的三句话）

1. **素材可用**：16 个招式的动画状态在引擎里真实跑出来了（含 UBW 3300、弓射 1100/1150、
   对空 1050/1051、踵落 1200）——换装到我们的 `archer` 时，这些动作的精灵链是通的。
2. **素材有缺口**：重脚 `c`、受身、倒地攻击、大跳在该角色里是死指令，**对应表现没有可用实现**，
   P6 若需要这些动作必须自绘或从别处补。
3. **失败项都不是我们的问题**：要么是原作指令优先级遮蔽（超必杀被短指令抢先），
   要么是本装置按键注入的限制，要么是 OCR 没读出来 —— 逐项列在 §2 表格里。
