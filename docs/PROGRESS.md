## 2. 已完成

### 2.1 方向（总纲，2026-10-02 定版）

- **人人能放**：没有任何搓招。A/S/Z/X = 不耗气普通招式，带 C/D = 耗气技能。
- **量大管饱**：20 个招式（12 普通 + 8 气键技能）。
- **反制为纲**：深度来自「用自己的招式拆解对手的选择」，不是连段。
- **操作分层只有一条规则**：只用 A/S/Z/X → 不耗气；带 C/D → 耗气。C、D 键之前完全空闲，所以这个分层**不需要新增按键、不改引擎键位、不重做状态机**。

### 2.3d 玩法规则修正（2026-10-31）

复核时发现四处**出招表/注释写着的规则，代码并没有兑现**。共同点：都不报错、都能玩，只是承诺是空的。

| # | 问题 | 之前 | 现在 |
| --- | --- | --- | --- |
| 1 | **射箭不扣气** | 出招表写 300 气、路由要求 300 气，但状态里没有扣气行 → **300 气可无限射** | 1000 加 `powerAdd{value: -300}` |
| 2 | **升斬不扣气** | 同上，承诺 400 | 1100 加 `powerAdd{value: -400}` |
| 3 | **幻想崩坏多扣气** | 路由只要 800 气，状态里扣 1000 → 扣穿到 0，"800 可放"变成"必须攒 1000" | 改成 `-800`，与出招表/movelist.dat 一致 |
| 4 | **闪身收招仍在滑** | 状态级 `velSet` 每 tick 重写速度，`if time = 12` 置的 0 下一 tick 被覆盖 → 后 8 tick 可惩罚窗口**不存在** | 位移按 `time < 12` / `time >= 12` 分段 |
| 5 | **跳劈不是 overhead** | `guardflag: MA` = 上下都能防，但出招表、用途表、AI 注释都写"overhead 破防" | `guardflag: H` = 只能站防 |

配套：**AI 直接 `changeState`，绕过 `command.zss` 的气量门槛** → 给 AI 的射箭规则补上 `power >= 300`，否则 AI 零气照样白嫖（扣气被引擎夹在 0）。

同时修正了出招表里的两处过期说法：闪身是 **12 tick 无敌 + 8 tick 可惩罚**（原文写"前 2 帧 / 后 14 tick"），无敌段按动作切成 4~6 个元素但总长必须正好 12 tick。

### 2.3e 端到端全招式验收入口（2026-10-31，新增）

`pwsh -File tests/p6/verify_moves.ps1 -Pass all` —— 一条命令，**30 条配方 + T2 完美防**。

做法：把一份遥测探针（`tests/p6/fixtures/archer_probe.zss`，`printToConsole`）挂进 runtime 角色，
每 tick 输出 `状态号 / time / 位置 / 速度 / 气量 / 双方生命 / p2BodyDist / ctrl / 特效数量 / facing / var(20) / var(22)`；
脚本按键注入后按配方断言「进入的状态号、伤害、耗气、能否收招、位移」。
**所有期望值都从 `.zss` 源码算**（`hitDef.damage`、`StateDef` 头 `poweradd`、状态体 `powerAdd`），
避免「招式改了、断言还停在旧数字」。

它第一次跑完就抓到 5 个此前没人发现的真缺陷：

| # | 缺陷 | 根因（引擎层） |
| --- | --- | --- |
| 1 | **受击框从来没预放大**，一片招恒 0 伤害 | `archer.air` 头声明「Clsn 已 ÷0.48」，实际只做了 Clsn1，未做 Clsn2（368 条）；Clsn1/Clsn2 都乘 `size.xscale` |
| 2 | **投技三段全空** | 动画只剩 5 tick + AIR 里一条 `Clsn1` 都没有（`clsnCheckSingle` 要求 `len(clsn1)>0`）+ `hitflag: M-` 的 `-` = `HF_MNS`（只打从没被打过的目标） |
| 3 | **T1 二段对重拳永远进不去** | 命令缓冲按 gameTime 计时，命中停顿期间 gameTime 走、状态不走 → 窗口被吃掉 13 tick；36 才够 |
| 4 | **四条配方「假失败」** | 验收脚本把设计方向 `fwd` 写死成物理右键；引擎里物理 L/R 恒等于世界 ∓x（`fbFlip`），p1 转身朝左后全部镜像 |
| 5 | **T2 完美防稳定 FAIL** | 测试方式「一直按住 ←」只产生一次边沿，3 tick 后窗口归零 → 奖励分支结构性不可达 |

第 4 条最值得记：**测试脚本的 bug 伪装成了游戏缺陷**。因此 `Move-Near`/`Move-Far` 现在
返回成败并在报告里标 `POS-FAIL`，不再把走位失败写成 `STATE-MISS`。

验收数字（2026-10-31）：招式 **30/30 PASS**；T2 **PASS**（蹲防 3 次、其中 2 次落在精防窗口内、
特效环 10 行）；T3 前摇取消 **66/66 伤害、−465/−465 耗气**（365 + 手续费 100）。
位移按面向折算：前冲闪 +121.00 / 后撤闪 −110.00 / 下闪 0.00 / 后撤投剑 −91.25 / 突进斩 +82.50。

### 2.3f 启动守卫（2026-11-03，新增）

`pwsh -File scripts/run_game.ps1` 现在会先扫 `external/mods/*.lua`，有残留就**拒绝启动**（exit 4）
并列出文件名；确实要加载才加 `-AllowMods`。

起因：负责人报「进不去」—— 引擎停在 `NOW LOADING`，弹 `Error: .\external\mods\kofprobe.lua:1`。
那是 10-31 调查 Lua 能力时留的一行 `error()` 探针，而 `external/script/main.lua:3986` 会
`require` 该目录里**每一个** lua。该目录被 gitignore，`git status` 永远干净，只有启动会撞上。

同一轮还修掉一个位置最坏的旧 bug：`Start-Process` 没加 `-PassThru` 时不返回对象，脚本读
`$proc.Id` 在 StrictMode 下抛错 —— **游戏已经拉起来了，脚本却 exit 1 报失败**。
修完后正式入口实测 `exit 0` + PID 打印 + 窗口 `Responding=True`。

细节与实测数据见 [`iterations/20261103-runtime-launch-guard.md`](iterations/20261103-runtime-launch-guard.md)。

### 2.3g 手感三项：距离 / 硬直 / 不可防（2026-11-03）

负责人实测反馈「打不到、没硬直、连不上」。三条都先量化再修，工具是新增的
`tools/frame_data.py`（帧数据 + 帧优势，纯标准库，`--check` 可直接进回归）。

| 问题 | 真因 | 结果 |
| --- | --- | --- |
| 刀打到人不掉血 / 重击贴脸 | **判定窗口和刀锋错帧**：210 伸得最远的一帧（77.3）原来没有判定框；230 的框比刀短 18.7；400 短 16.8 | 判定框逐帧跟刀走，重斩起手 12 → 10 |
| 打中反被反打、无法连招 | **帧优势为负**：`adv = hittime − (total − startup − 1)`，轻斩 −6。hittime 抄的是 KFM（11），但动画比 KFM 长 40~60% | 收尾巴 + 提 hittime：轻斩 −6 → **+4**，重斩 0 → **+2**，蹲系 −3 → +3 |
| 无限剑制被防住 | 投射物 `guardflag: MA`，站着就能防 | 状态级 `assertSpecial{flag: unguardable}`，必防假人下仍打 **96** 伤害 |

> ★ 2026-11-03 第二次：96 这个数**本身也不合格** —— 花整条槽（2000 气）打 96，
> 而半条槽的 Super 有 195，是倒挂。单把剑 16 → **50**：实测 6 连 ≈ **300**，
> 10 连上限 500。`verify_moves` 的门槛随之 48 → 200，退化回 96 会直接 FAIL。

验证：`verify_moves.ps1 -Pass moves` **30/30 PASS**；终极技做了**正反两组对照**
（带 flag 96 / 去掉只剩 20 削减），并新增 `-DmgRule atleast` 把这个差别变成会 FAIL 的断言。

细节见 [`iterations/20261103-feel-distance-stun-unguardable.md`](iterations/20261103-feel-distance-stun-unguardable.md)。

### 2.3h Fighter B：反制手段（2026-11-03 续）

负责人接着反馈「test fighter B 无限远程 + 高硬直，几乎没有反制手段」。四条机制问题：

| 问题 | 真因 | 结果 |
| --- | --- | --- |
| 无限远程 | 气弹 `poweradd: 40` = **发波倒赚气**；AI 冷却 90 + 波活 130 = 132 tick 一轮，屏幕 98% 时间有波 | 气 40 → **0**、波活 130 → **80**、冷却 90 → **140** ⇒ 每轮留 102 tick 空窗 |
| 高硬直 | 气弹 `hittime 16` / `air.hittime 20` / 退速 −6 | 12 / 16 / −4 |
| **没有反制手段** | 气弹判定框高 **120**、还往地下伸 20，而跳跃顶点只有 ~80 ⇒ **几何上跳不过去，只能防** | 框改为素材外框 + 2：`-58,-86,72,2` |
| 「人机出拳比我刀远」 | 210 框 **105** 而画面只到 **81**（240 差 21、1100 差 16）= 空白判定 | 全部改成「框 = 画面 ± 2」；反向的（框比画面短 5 处）一并补齐 |

另外两条：`210` 有 **16 tick**、`230` 有 **8 tick** 没写 `Clsn2` ⇒ 招式中途无敌、玩家反击打空
（补 `Clsn2Default`）；`210` 显式写 `guard.hittime: 13` 让"被防"真的变成劣势（+2 命中 / **−5** 被防）。
`_template` 与 `test_fighter_a` 同批缺陷一起修（它们是新角色的克隆源）。

工具修了三个真 bug：`audit_moveset.py` 的 `SC = 0.48` 硬编码（对其他角色全是假警报）、
`frame_data.py` 对击倒/击飞招误判、以及新增 `guard`/`adv_gr` 两列。
`frame_data.py --check` 已接进 `scripts/test.ps1 -Suite frame`，四个角色全 PASS。

**第二轮（2026-11-04，负责人反馈"依然无限波 / 大招威力不够"）** —— 第一次修错了两处：

| 错误 | 真相 | 定稿 |
| --- | --- | --- |
| 以为"3 秒一发"就有节奏 | 一波约 1 秒横穿屏幕，防住后只剩 1.7 秒，对手已在准备下一发 ⇒ 体感仍是"一直在防"；而且 EX(2 发)/Super(3 发) 当时**完全没节流** | ⑥ 冷却 140 → **240**（≈4.7 s）+ **`numProj = 0` 空场才发**；EX 300、Super 360 |
| 以为"框对齐画面"就等于"跳得过去" | 框对齐的是**左右和上下边缘**，能不能跳只看**画面顶端 vs 跳跃顶点**。素材 84 px 高浮在 40..123，`apex = 80.2` ⇒ 顶从 100 变成 126，**更跳不过去** | 发射点压到 `offset y = +18`（画面 −18..65），框 `-58,-83,72,0` 与画面严格一致 ⇒ 跳跃窗口约 16 tick |

大招伤害是**结构倒挂**，不是数字小：Super 花 1000 气打 195，终极花 2000 气（整槽）打 96
（10 把剑 ×16，只连到 6 把）。单把 `16 → 50`，实测 **300**，上限 500；
`verify_moves` 门槛 `48 → 200`，退化回 96 会 FAIL。

踩坑：`numProj` 在 ZSS 里**无参**（`compiler.go:3189` 不读括号），必须写裸 `numProj`，
写成 `numProj()` 编译失败而 `validate_character` 看不出来 —— 只能靠引擎加载验证。

## 6. 文档中已记录的教训（防重演）

- 换任何资源（精灵/音效/调色板）都要**重映射引用 + 有校验规则兜底
- Bash heredoc 会吞反斜杠，导致正则**静默失配** → 用 `[0-9]` 或字符串处理
- 精灵可以用**形状分析**（填充率/行宽分布）判断是人物 / 剑 / 特效帧，不必依赖看
- 输入测试失败时，先怀疑测试装置，再怀疑角色（已踩过两次：字母键注入不通、按键时机太早）
- 2026-10-31 第三次、也是最贵的一次：**验收脚本把设计方向写死成物理键**，p1 一转身，
  四条配方全部镜像，报告上表现为「三个技能坏了」。教训已固化成两条：
  ① 方向键一律按 `facing` 换算（引擎里物理 L/R = 世界 ∓x，不是角色的后/前）；
  ② 走位失败必须标 `POS-FAIL`，不许伪装成 `STATE-MISS`。
