# KingOfFate 术语表

> **用途**：后续讨论、任务交接、文档撰写时统一用词，避免"同一个词指两件事"。
> 最后一节列出**容易误解的词**，那些是本项目已经踩过坑的地方。
>
> 相关文件：[总纲](game-design-charter.md)（方向）· [进展总览](PROGRESS.md)（现状）

## 一、设计与方向（总纲用语）

| 术语 | 一句话解释 | 本项目的具体含义 |
| --- | --- | --- |
| **人人能放** | 任何人都能轻松放出技能 | 禁止搓招。所有技能都是「方向+按钮」或「按钮+按钮」，一次输入就能出 |
| **量大管饱** | 招式数量多、出手密度高 | 每角色下限：12 普通 + 8 气键技能。**注意：这个价值来自"正反馈频率"，不是"招数多"** |
| **反制为纲** | 深度来自拆解对手的选择 | 出招时预判对手怎么应对 → 被反制后立刻有下一个选择。**不是固定的招式克制表** |
| **动态读招** | 对手出招时你实时判断应对 | 逐回合的判断，不是背表 |
| **正反馈循环** | 每次成功释放技能都是一次小胜 | 技能数量 = 反馈频率。**因此演出长度会吃掉反馈频率** |
| **三层深度模型** | 深度由三部分承载 | ① 广度（招式多）② 空间与惩罚（距离/空挥/确反）③ 可选技术（不设门槛的进阶） |
| **情境标签** | 给每招打的属性标记 | 距离 × 高度 × 速度 × 飞行 × 破防 × 部位。**用来替代"关系矩阵"** |
| **情境覆盖** | 检查是否覆盖所有情境 | 有没有"无人能应对"或"人人都有解"的情境 |
| **制造情境** | AI 的目标：把对手逼进有利局面 | 替代"算最优连段"，也更可实现 |
| **可被确反的收招** | 出招后有一段"动不了"的时间 | 对手可以在这段时间打你 → **这就是深度的来源** |
| **画面知识** | 只对"这套美术"成立的数据 | 判定框形状、轴心、移动速度、每招音效、投射物偏移 → **从原作者那里搬** |
| **战斗框架** | 对"这个游戏"成立的数据 | 状态编号、取消链、气量经济、AI、硬直约定 → **我们自己的，不搬** |

## 二、操作与输入

| 术语 | 含义 |
| --- | --- |
| **普攻 / 普通招式** | 只用 `A`/`S`/`Z`/`X` 打出，**不耗气** |
| **气键技能** | 输入里**带 `C` 或 `D`**，消耗气槽。`C`=中型 300~400 气，`D`=大型 600~800 气，`C+D`=终极 2000 气 |
| **意图方向** | 方向键在气键技能里表达"我想干什么"：`←`拉开 · `→`突进 · `↓`压制破防 |
| **投技** | 贴身时抓对手，**破防**（防住了也能打进去），不耗气 |
| **搓招 / 指令技** | 需要按方向序列（如 ↓↘→+A）的输入。**本项目已全部废除** |
| **禁招（退役）** | 代码还在但没有任何输入能进（例如状态 1010 旧 EX），交付前删除 |

## 三、战斗与判定

| 术语 | 一句话 | 备注 |
| --- | --- | --- |
| **tick / 帧** | 引擎的最小时间单位，**每秒 60** | 20 tick ≈ 0.33 秒。项目的时序数字单位都是 tick |
| **起手（发生）** | 出招到攻击生效的等待 | 越短越"先手" |
| **判定（持续）** | 攻击框开启的时长 | 本项目现在统一 3 tick |
| **收招（硬直）** | 攻击框关闭后到能动的等待 | **可被对手确反**，所以是设计重点 |
| **判定框 `Clsn1`** | 攻击的范围与高度 | 写在 `.air` 里 |
| **受击框 `Clsn2`** | 自己能被击中的范围 | **缺失 = 出招期间无敌** |
| **外缘** | 判定框离角色原点的最远水平距离 | 用来和"素材实际伸展"对比 |
| **垂直带** | 判定框的上下边界（y 值，越负越高） | 用来区分上段/中段/下段 |
| **上段 / 中段 / 下段** | 判定框的高度带 | 站姿受击框约 y 0~−94，所以 y ≤ −95 才算上段 |
| **确反** | 在对手收招期间打他，白嫖 | **深度的主要来源** |
| **受身 / 起身** | 被击倒后的翻身与受身 | 170 动作（起身）刻意无受击框 = 起身无敌，是常规设计 |
| **推挤盒** | 角色互相推开的范围 | `[Size]` 里的 ground/air back/front |
| **空挥** | 打空了的攻击 | 距离控制的基础 |

## 四、引擎与文件格式

| 术语 | 全称 / 含义 |
| --- | --- |
| **AIR** | 动画文件（`.air`）。按"动作号"组织，每个动作是一串元素行 `组,图,x,y,tick` |
| **动作号** | AIR 里的动画编号（如 `200`、`1100`）。**和状态号是两个东西，只是我们让它们对齐了** |
| **元素 / element** | AIR 里的一行 = "显示某张图若干 tick" |
| **Clsn** | Collision，碰撞框的声明前缀 |
| **SFF** | 精灵文件（`.sff`）。存精灵 + 调色板 |
| **SND** | 音效文件（`.snd`） |
| **CMD** | 命令定义（`.cmd`）。把"按键序列"翻译成"命令名" |
| **ZSS** | 本项目自己用的状态脚本方言（IKEMEN 的），存状态机 / 路由 / 帧数据 |
| **StateDef** | 一个状态（`.zss` 里的 `[StateDef 200;`） |
| **状态号** | 状态机里的编号。**受击/倒地 5000+、投技 810 等是公共约定，不要重写** |
| **var(n)** | 状态内的变量。项目约定：`var(3)`=链等级、`var(4)`=取消窗口开、`var(10)`=投射物闩锁 |
| **projId / projanim** | 投射物的编号 / 用的动画 |
| **xscale / yscale** | 角色缩放。**本项目设 0.48**（把 162×249 的高清素材缩到原大小） |
| **clsnBaseScale** | 引擎的内部量：**所有判定框都会乘以角色缩放**（见下方"易误解"） |
| **P 阶段** | 项目阶段：P0 骨架 → P1 架构实测 → P2 模板 → P3 首个角色 → P4 第二个角色 → P5 资产工具链 → **P6 第一个正式美术角色** |
| **Gate** | 阶段的验收关卡。Gate N = 该阶段的第 N 个必须通过的检查 |

## 五、项目专有概念

| 术语 | 含义 |
| --- | --- |
| **三层映射** | 骨架（`.zss`）↔ 美术（`.sff`）↔ 映射表（`asset_map.csv`）。换美术只动映射 |
| **占位素材** | KFM 的占位图/占位数值。**占位素材绝不能当正式资产验收** |
| **高清素材** | 当前用的 `Nameless_Archer`（1803 精灵 / 423 动作，站立 162×249） |
| **kuri 版** | 早期的低分辨率素材（54×120）。保留为降级退路，也是**画面知识的来源** |
| **验收清单** | `P6-acceptance-checklist.md`，逐条"怎么验 + 结果" |
| **待处理清单** | `TODO-backlog.md`，有序的执行清单。**新条目先加这里，不随手开工** |
| **精灵映射** | `asset_map.csv`：我们的动作号 → 源素材的组/图 |
| **特效帧 ≠ 人物帧** | 源素材里有些"动作"其实是斩击光效。**映射前必须验证**（人物帧最高 ≥150px） |

## 七、易误解的词（**本项目踩过坑的地方**）

| 说法 | 真实含义 | 踩过的坑 |
| --- | --- | --- |
| **"攻击范围"** | 说法模糊 | 分清两个数：**判定框**（能打到人）与**素材伸展**（画面上武器伸多远）。两者要一致，不一致就是"动画打到了但没打中" |
| **"缩放只影响画面"** | ❌ 错 | `clsnBaseScale = {xscale, yscale}` —— **判定框也乘缩放**。设 0.48 就等于判定框也缩到 48%。AIR 里的 Clsn 数值必须 **÷0.48 预放大** |
| **"逐帧 Clsn2 覆盖整段"** | ❌ 错 | `Clsn2: N` 只作用于**紧邻的那一个元素**。要覆盖整段必须写 `Clsn2Default:` |
| **"动作 200 就是状态 200"** | 巧合 | 两者是不同概念。5000+ 是公共受击/倒地约定，**不要重写** |
| **"有伤害值就会造成伤害"** | ❌ 错 | **投射物动画（`projanim`）自己没有 `Clsn1` 就没有碰撞框 → 完全不造成伤害，且引擎不报错** |
| **"换个音效库就行"** | ❌ 错 | 脚本里的音效编号在新库里可能**根本不存在** → 角色变哑，引擎不报错。换库必须重映射引用 |
| **"校验 PASS 就没问题"** | ❌ 错 | 校验器解析引用，**不解析 ZSS 语法**。`hitsound::`（双冒号）能让整个角色加载失败而校验器不报 |
| **"输入测试没反应 = 角色有问题"** | 先怀疑装置 | 测过两次：一次是字母键注入不通，一次是第二次按键早于窗口开启。**先怀疑测试装置** |
| **"受击框缺失"** | = 出招无敌 | 逐帧 Clsn2 只覆盖一帧时，**其余帧全是无敌帧** |
| **"收招 = 收招动画"** | 容易混 | 收招 = 攻击框关闭后到能动的等待（可被确反的窗口），和动画播不播完无关 |

## 八、常用缩写

| 缩写 | 全称 |
| --- | --- |
| `AIR` / `SFF` / `SND` / `CMD` | 动画 / 精灵 / 音效 / 命令文件 |
| `ZSS` | 本项目的状态脚本方言 |
| `attr` | 攻击属性（`S`=站姿 `A`=空中 `SP`=特殊投射物 `NT`=投技） |
| `hitflag` | 命中标志（`M`=必须命中 `A`=空中 `F`=地面） |
| `guardflag` | 可否防御（`M`=可防 `A`=空中 `L`=低段） |
| `AIR/sprpriority` | 绘制层级 |
| `PowMax` | 调试用满气（引擎的 F3 热键） |
| `F3` | 引擎调试热键：`powMax(1); powMax(2)`，两次满气 |
