## 4. 八条必须知道的事实（都带实测出处）

1. **`.air` 的 `Clsn1` 会沿用到下一次声明** —— 不在判定帧之后写 `Clsn1: 0`，
   攻击框就会一直保留到收招结束，**实际判定窗口比 Frame Data 的 Active 长**。
   复查时 9 个新动作全踩了这个坑（最长多 24 tick）。
   *依据*：MUGEN/IKEMEN 的 `.air` 语义（Clsn 框按"当前声明"生效直到下次声明），
   旁证是模板自身的 Action 200/240 都在收招帧显式写了 `Clsn1: 0`
   （若框不沿用，这两行毫无意义）。**尚未做 A/B 实测**，见 §8 遗留项 9。
2. **`call` 语句必须写分号**，`var(n) := x` 也要写分号；
   **`call` 不能内联在 `if` 条件里**（要先 `let x = call F(...)`）。
   写错是**加载期致命错误**（Panic + 崩溃日志），但 `scripts/test.ps1` 发现不了。
3. **`pwsh -File` 无法把逗号列表绑成数组参数**：
   `-Steps 1,2,3` 会变成数字 **123**，`-Phases 'a','b'` 会把多出来的值
   **按位置绑到下一个参数**（甚至静默绑到 `-Stage`）。
   本项目所有多值参数因此一律用"一个逗号连接的字符串"。
4. **引擎的控制台输出不可指望**：直接 `RedirectStandardOutput` 得到空文件；
   要判断"有没有出错"，看 `engine/ikemen-go/save/logs/Ikemen_*.log` 有没有新文件，
   以及截图里的游戏内控制台。
5. **合成按键的持续按住会衰减**：一次"按下"大约只维持 1.2 s 的"前进"意图
   （引擎在 forward buffer 清空时把角色退回状态 0）。要走一段路，就按**多次**。
6. **取消窗口长度 = 目标状态自己的动画长度**（轻招只有 ~0.28 s）。
   **Super cancel 的正确输入**是"先 236+A 进必杀，紧接着再 236+A"——
   `QCF2_x` 的缓冲独立存在（`time = 45`），第二次 A 落下时整个 236236+A 已经成立。
   这也是 `.cmd` 里 **QCF2_x 必须排在 QCF_x 之前**的原因。
7. **防御是引擎级的**：按住"后" + `guardflag` 匹配 → 直接进公共状态
   150/152（实测 20→150→151→130）。角色**不需要**自己路由进防御状态；
   KFM 的 `blocking = $F,x` 只是它的额外入口。
8. **采样方式决定结论**：KFM 的 AI 里投技/扫腿占比高，投技**不可防** ——
   用"待机被 AI 打"的方式测防御，采样到的全是受击/倒地帧。
   把攻击者也变成可控的（把 P2 的按键也重映射到可注入键）之后，一次就拿到防御证据。

## 5. 本阶段明确**不做**的

- **平衡**（伤害模型、胜率、Tier）：P10。本轮只保证数值"不离谱"。
- **表现层**（superPause、镜头、闪光、暗转、胜利台词、多姿势胜姿）：P7。
- **原创美术/音频**：P5/P6。当前是 KFM 占位素材（CC-BY-NC，`prototype_only`）。
- **把蹲/跳/必杀的实现补进 `_template`**：本轮**只改模板文档**，不改模板战斗逻辑；
  是否把 Fighter A 的这些动作回灌模板，留给 P4 决定。
- **任何框架化**（角色继承、生成器、技能 DSL、第二套气槽/取消系统）：合同 §29 禁止。
