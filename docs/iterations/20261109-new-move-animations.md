## 一、反馈与一个更好的答案

负责人试玩后：「你好像做了一些技能，但是动作都是复用的没有新的，我有点分不清，
是不是还是设计一些新动作比较合适？素材从网上直接查找或者你基于现有的重新绘制
都可以。」（并提示 7897 代理已开。）

**结论：没联网下载，也没 AI 重绘，而是从仓库里已登记的原始素材包中取出了
306 个从未被映射过的动作。** 这三条路的对比：

| 路径 | 判断 |
| --- | --- |
| 联网找新素材包 | 查到 AK1 的 Emiya (Archer) 1.0.0 by Seravy、MFFA 的 Fate 合集（含 "Custom Sprited High Res: aka65535 / Sho"，正是本项目素材源）。但这些都是**不同作者的重绘版**，调色板 / 轴心 / 尺寸与当前 SFF 不一致，混进来会更突兀；同人包授权还要重走 `assets/LICENSE_MANIFEST.csv`，论坛下载多需登录。成本最高、收益最不确定 |
| AI 图生图重绘 | 单帧可画，但总纲与项目记录都点名「AI 重绘单帧易、连贯动画难」；8 招 × 6 帧要保持同一角色连续姿势，风险极高 |
| **本地原始素材包** ✅ | `assets/imports/archer_hires/Nameless_Archer/Archer.sff` 有 **1805 精灵 / 187 组 / 423 动作**，当前 `archer.sff` 只重映射了 470 个。源包里 **306 个动作的精灵组从未被映射**——同一套高清素材、同一调色板、同一轴心、同一作者，且授权已登记 |

关键盘点数据：

```text

原始 Archer.sff    1805 sprites / 187 groups / 423 actions（SFF v1）
```

源包还带 `説明書.txt`，招式表里正好有本轮需要的方向特殊技：

## 三、四个必须记下的坑

### 3.1 这批源动作不是「起手/判定/收招」三段式

它们是作者原本的**完整连击**，帧 3 常常是收招/回旋姿势，reach 只有 30~47
世界单位；强塞进我原来的 6 元素结构后，判定框和刀根本不在同一帧（项目里
210 重斩踩过的同一个坑）。

修法：逐帧解码 RGBA，量可见像素相对轴心的最右延伸（× `xscale 0.48`），
把**每组 reach 最大的帧重排到第 4 个元素**（ZSS 的 `animElem = 4` 不变，
所以 ZSS 状态脚本一行都不用改）。例如 2610 的 frame 4 reach 53.8 世界，
而 frame 3 只有 46.1。

### 3.2 判定框必须按新画面重算

旧框沿用 `200/210/230/240/1100` 的值，新画面下框比画面长 30~50 世界单位
= 看不见的判定（HANDOFF §7.1 明令禁止）。按 `框 = reach + 3 世界` 重算：

| 招 | 判定帧 reach | 框右边界 |
| --- | --- | --- |
| 260 | 65.3 | 68.2 |
| 261 | 53.8 | 56.6 |
| 262 | 54.2 | 57.1 |
| 263 | 45.6 | 48.5 |
| 264 | 63.8 | 66.7 |
| 265 | 51.8 | 54.7 |
| 266 | 73.9 | 76.8 |
| 267 | 60.5 | 63.4 |

`frame_data.py` 8 招「框 vs 画面」全部 ok。

### 3.3 贴身漏判

框 x 起点沿用 38 素材 = **18.2 世界**，而 `Move-Near` 后两人只隔 10~16，
对手整个人落在框起点之前。266 把起点移到 0 后覆盖到贴身。
（与项目里 1100 升斬特意加 8 px 前压是同一个现象。）

### 3.4 1500 组不适合做后撤踢

第一版 `←+Z` 用 1500（空中旋转）：整组 reach 最大只有 47 世界，判定帧的
可见 bbox 还大幅偏左（x 到 −136，是后空翻姿势），扩框、前移起点都救不回来，
实测 0 伤害。换成 `245 / 6-11`（后半段地面连击，reach 73.9）后 27/27 PASS。

另外两处连锁调整：
- ← 系后撤减半（−4~−5.5 → −2~−2.5，约 6~7.5 px），否则短 reach 的招够不到；
- 8 条 ZSS 头部注释同步成「SFF 组 26x0（源包 action X）」与新位移数值。

### 3.5 脚本小坑（两次）

- 批量改 AIR 帧引用时，正则错把 **sprite image number** 当成 duration，
  帧时长变成 `0,1,2,4,5,6`。改成显式捕获 5 个字段的第 5 个。
- 按 `[StateDef N;` 区间切片去改注释会**错位一格**：注释块写在 StateDef
  **之前**，切片里装的是下一个状态的注释。改成按全文出现顺序替换。
- 又一次踩到 Bash heredoc 吞反斜杠（`\d` → `/d`），内联 Python 正则静默失配；
  结论仍是：写脚本文件再执行。
