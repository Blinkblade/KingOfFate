## 技术实现

### 1. 为什么要有 P1 Lab 这个副本

直接改 `engine/ikemen-go/chars/kfm_zss/` 有三个问题：它在 submodule 里（会污染引擎工作区）、
它是上游素材（改动不可追踪）、它无法进 PR评审。

所以 P1 Lab 的做法是把角色复制成**本仓库跟踪**的副本，实验改动都在副本上做，
再用 `sync_game_content.ps1` 单向同步到运行时。这样：

- 引擎 submodule 全程保持字节级干净；
- 每次改哪个文件、改成什么，都在 git 历史里；
- 实验结束后可以把改动还原，副本回到与上游一致的状态。

### 2. 怎么"看见"引擎内部（观测装置）

IKEMEN 没有角色状态日志。P1 用引擎自带 Lua 调试层（`external/script/debug.lua`）
作为观测窗口：

- `Ctrl+D` → 左下角逐帧打印 `State No / CTRL / Type / MoveType / Physics / Time`
  与双方的 `LIF / POW / RED / ATK / DEF / GRD / STN`，以及
  `ActionID / ElemNo / Time(a/b (c/d))`；
- `Ctrl+C` → 显示判定框（Clsn1 红 / Clsn2 蓝）。

然后 `capture_match.ps1` 负责把这一层打开、注入输入、按间隔抓帧；
`montage_states.ps1` 把每帧的读数条带裁出来拼成一张图。

**这条链路本身是本次迭代最花时间的部分**，因为踩了两个坑（见"已知问题"）。

### 3. 实验方法（每个实验的统一流程）

```text
记录基线 → 用 montage 读出基线数值
   ↓
改一个文件的一处地方
   ↓
sync 到运行时 → 重新跑同一命令 → 用 montage 读出改动后数值
   ↓
对比是否与预期一致 → 还原改动 → 再 sync 一次
```

**每次只改一处、只改一个文件**，否则无法归因。

### 4. 六个实验的结论（详细推导见 `docs/p1_experiments.md`）

| # | 改什么 | 观测到什么（数值） |
| --- | --- | --- |
| E1 | `kfm.const` 的 `walk.fwd 2.4 → 12.0` | 同 0.35 s 内从位置 56 变为冲至对手身前（被推挤盒截断） |
| E2 | `kfm.zss` 的 `damage 23 → 137` | `P2 LIF` 精确 `1000→977` / `1000→863`；集气与红血联动 |
| E3 | `kfm.air` 首元素 `2 → 20` 帧 | 动画总时长 **12 → 30**；`hitDef` 触发点第 4 → 第 22 tick |
| E4 | `kfm.air` 的 `Clsn1[0]` 放大十余倍 | 攻击框巨大化；受击框、精灵、伤害（仍 23）**全不变** |
| E5 | `kfm.cmd` 的 `name="x"` 改绑 `y` | `x` 键彻底失效；`y` 键改入 State **200**（顺序优先级） |
| E6 | `AI.zss` 链首插一条 `changeState 210` | 12 帧中 11 帧为 210；对手 `LIF` 全程 1000（空挥） |

### 5. 三条贯穿性结论

1. **整条执行链 100% 可在角色文件内验证，无需触碰引擎源码。**
   P1 期间引擎 submodule 的 `git status` 为空，HEAD 仍等于钉死基线。
2. **"改什么 → 变什么"是精确可预测的**，不是"看起来变了"。
3. **存在两个隐式的优先级系统**：命令路由顺序（E5）与 AI 规则顺序（E6）。
   两者都是"先出现者胜"，排序失误会导致**静默失效**——这是后续阶段最容易踩的坑。

## 已知问题

1. **合成按键注入只有 TAB / RETURN 可达引擎。**
   字母键、方向导航键、COMMA 均无法送达，导致无法在一次运行内测组合键（`x+y`）。
   P1 的应对是把运行时键位锁成 `x=TAB`、`y=RETURN`，并在文档中明确记录该前提。
   **这是一条真实约束，不是被隐藏的假设。**

2. **`Ctrl+D` 覆盖层曾静默漏触发。**
   第一次 AI 实验的截图里完全没有状态读数，导致整轮作废。
   根因是按键发送后没有校验覆盖层是否真的出现。
   修复：`capture_match.ps1` 增加覆盖层像素检测，并在发送后最多重试 3 次；
   重跑时报告中出现 `overlay not detected (attempt 1)` → `overlay ON (attempt 2)`，
   证明修复生效。

3. **`pwsh -File` 无法绑定数组参数。**
   `-HoldSeqVK 0x09,0x2D` 报"无法转换为 System.Int32[]"。
   改为字符串参数 + 脚本内 split 解析（支持 `0x` 十六进制）。

4. **GDI+ `LockBits` 裁剪返回整图 stride**，导致逐像素跨帧比较不可靠。
   改用"裁条带 + 人工判读"的 montage 方案，证据可靠性反而更高。

5. **E1 未能直接读出速度倍率。**
   舞台宽度不足以让高速角色自由跑满，角色撞上对手后被推挤盒截断，
   所以只证明了"常量生效"，没有读出 5×。
   如实记录在 `docs/p1_experiments.md` §3 与 §10，并给出改进方向
   （P2 用 `displayToClipboard` 输出 `pos x`，改测 time-to-contact）。
