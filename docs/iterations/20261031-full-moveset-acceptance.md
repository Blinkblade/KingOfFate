## 本次目标

以前判断「这招对不对」靠的是**人肉试玩 + 看截图**。本轮把这件事变成一个可重跑的命令：
`tests/p6/verify_moves.ps1` 用角色内的遥测探针（`printToConsole`）把每一 tick 的
状态号 / 位置 / 气量 / 双方生命 / 判定框特效数量写成 CSV，再由脚本对 30 条配方逐条断言
「进入的状态号对不对、伤害对不对、耗气对不对、收招能不能动、位移多少」。

目标不是「测得多」，而是**每条断言的期望值都从源码算**（`.zss` 的 `hitDef.damage`、
`StateDef` 头 `poweradd`、状态体 `powerAdd`），避免「招式改了、断言还停在旧数字」的假通过。

结果：入口做出来了，而它第一次跑完就抓到 **5 个此前完全没被发现的真缺陷**。

## 五个真缺陷

### 1. 受击框从来没做 Clsn 预放大（368 条坐标）

`archer.air` 文件头自己声明「所有 Clsn 已 ÷0.48 预放大」，**Clsn1 做了、Clsn2 没做**。
后果：受击框的世界尺寸只有 28.8 × 79.2（画面上是 78 × 120），比推挤盒（约 66 宽）还窄，
判定远端 50.9 的蹲 A **够不到**对手受击框起点 57.8 —— 蹲 A / 空 X / 蹲 S 等一片招恒 0 伤害。

依据是引擎源码而不是猜测（`char.go` 的 `updateClsnScale` / `clsnCheckSingle`）：
Clsn1 与 Clsn2 都乘 `size.xscale`（本角色 0.48），且头部声明的 `Clsn2Default`
是**整个动画的累加器**，不预放大就必然只有设计值的一半。

修法：`.tmp/scale_clsn2.py` 把全文件 368 条 `Clsn2` 坐标 ×(1/0.48)，`Clsn1` 一条不动，
保留 CRLF。修完 `400` 蹲 A 24/24、`640` 空 X 48/48 通过。

### 2. 投技「三段全空」：时长、攻击框、`hitflag` 各错一处

| 层 | 现状 | 后果 |
| --- | --- | --- |
| 动画时长 | `[Begin Action 800]` 每帧被写成 1，整段只剩 **5 tick**（注释写的是 23） | 抓取窗口几乎没有 |
| 攻击框 | AIR 里**一条 `Clsn1` 都没有** | `clsnCheckSingle` 要求 `len(clsn1) > 0`，所以 `hitDef` 形同虚设 |
| `hitflag` | 写成 `M-` | `compiler.go:flagSub` 把 `-` 解析成 `HF_MNS`，`char.go:10673` 的判据是 `HF_MNS != 0 && hittmp > 0 → 打不中`，等价于「只抓从没被打过的目标」 |

修完前投 / 后投都是 **150/150**（800 的 60 + 810 的 `targetLifeAdd` 90）。

### 3. T1 同键二次的窗口被「命中停顿」吃掉

`CanTap()` 要求 `var(4) = 1`（判定帧已开始），四招判定帧起点不同：
A=6 / Z=5 / X=9 / **S=13**。窗口最初 12 tick → 重拳物理上不可能；改到 26 后
A/Z/X 全过、S 仍 MISS。逐帧数据给出原因：**命令缓冲按 gameTime 计时，而命中停顿期间
gameTime 照走、状态却不执行** —— 实测一次重拳命中吞掉 13 个 gameTime tick（g429 → g442），
26 tick 的窗口正好被吃干净。改到 **36** 后 251 = 112/112。

三处注释（`archer.cmd` / `command.zss` / `archer.zss` / `movelist.dat`）已同步成 36。

### 4. ★ 验收脚本自己的方向键语义错了，制造了四条「假失败」

这是本轮最值得记的一条：**测试脚本的 bug 伪装成了游戏缺陷**。

`$DirToButton = @{ fwd = 'right'; back = 'left' }` 把设计方向直接写死成**物理键盘的左右**。
而引擎里（`char.go:6510` 的 `fbFlip = facing < 0` + `input.go:2802` 的 `B, F = R, L` 交换）
物理 LEFT/RIGHT **永远等于世界 −x/+x**，不是「角色的后/前」。

于是一旦 p1 转身朝左 —— 后投把 p2 扔到身后就会转身 —— 之后每条「方向 + 键」配方都被镜像：

| 配方 | 脚本想发 | 实际发出 | 现象 |
| --- | --- | --- | --- |
| 25 升斬 `→+C` | 前 + C | **后 + C** | 进的是 1200（配方 26 的招），1100 从未出现 |
| 26 后撤投剑 `←+C` | 后 + C | **前 + C** | 进的是 1100（配方 25 的招） |
| 28 突进斩 `→+D` | 前 + D | 后 + D | 未定义，什么都不发生 |
| 29 跳劈下压 `↓D` | ↓ + D | 不受影响 | 能进 1400，但两人已被顶在左右两条 stage bound 上（p1 x=+145.00 / p2 x=−144.96 / `p2BodyDist` 恒 224）→ 必然空振 0 伤害 |

报告上表现为「3 条 STATE-MISS + 1 条 0 伤害」，看起来完全像三个技能坏了。

修法：探针增加 `facing` 列；`Resolve-VKInvariant` 按 facing 把设计方向换算成物理键。
改完 25/26/28/29 一次全绿，位移量值也和隔离跑一致（后撤 −91.25 / 突进 +82.50）。

配套两条防复发措施：
- `Move-Near` / `Move-Far` 改成**返回成败**，失败时在报告里标 `POS-FAIL`，
  不再伪装成 `STATE-MISS`（走位失败会让整条配方空振，症状和真缺陷一模一样）。
- 位移表按**面向**折算正负（+ = 角色前方），否则同一招在不同 run 里符号会翻。

### 5. T2 完美防的测试方式结构性无法触发

机制是：`holdback` 的**边沿**把 `var(20)` 置 3，每 tick 减 1；进入格挡震动状态
（站防 150 / 蹲防 152 / 空防 154）时若 `var(20) > 0` → +80 气 + 格挡环特效（`explod 7191`）。

旧测试是「一直按住 ←」，边沿只发生一次，3 tick 后窗口归零，**此后每次格挡都必然
`var(20) = 0`** —— 奖励分支永久不可能走到，于是稳定报 FAIL。

改成蹲防 + 脉冲式补「后」（55 ms 按 / 35 ms 松），每次按下重新打开窗口。
为什么要蹲：站着按 ← 等于「往后跑」（公共状态 105），24 秒里 p1 跑了 171 tick、
只挡了 3 次，对手的招基本全打空，样本根本不够；蹲防不位移。

修完第一次跑就 **PASS**，而且证据是分层的：

```
样本 1455 行（"后"脉冲 220 次）
进入格挡震动状态 3 次（站防 0 / 蹲防 3 / 空防 0）
其中格挡那一 tick 精防窗口还开着: 2 次
精防窗口 var(20) > 0 的 tick 数: 658
出现精防特效环 numExplod(7191) 的行数: 10
```

探针因此增加了 `var(20)` / `var(22)` 两列 —— 「窗口没开」和「窗口开了但拳没落在里面」
和「拳落进窗口却没特效」是三件事，只看特效数量无法区分。

## 新增的可复用结论（已写进 HANDOFF）

| 事实 | 出处 |
| --- | --- |
| 物理 LEFT/RIGHT = 世界 −x/+x；角色的前/后由 facing 决定 | `char.go:6510`、`input.go:2802-2816` |
| `hitflag` 的 `-` = `HF_MNS` = 只打「从没被打过」的目标 | `compiler.go:flagSub`、`char.go:10673` |
| `clsnCheckSingle` 要求 `len(clsn1) > 0`：写了 `hitDef` 但没有 Clsn1 → 永远打不中 | `char.go:10485` |
| Clsn3（size box）用 `localscl`，**不**乘 `size.xscale`；Clsn1/Clsn2 才乘 | `char.go:10489-10501` |
| `Clsn2Default` 是整个动画所有帧 Clsn2 的并集，必须预放大 | 同上 |
| 命令缓冲按 gameTime 计时；命中停顿期间 gameTime 走、状态不走 | 本轮实测 g429 → g442 |
| `powerAdd` 会被 `Clamp(0, powerMax)`：满槽时增益观测为 0，但**扣气仍然精确** | `char.go:8807` |
| 遥测探针可以读 `facing` 与 `var(n)`，不必新增引擎侧能力 | `tests/p6/fixtures/archer_probe.zss` |
