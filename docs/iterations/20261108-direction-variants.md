```text

世界 y 下界 = -192 × 0.48 =  -92.2
⇒ 升龙框覆盖 y ∈ [-160, -92]
```

`verify_moves` 已证明它命中站立对手（46/46）。**对空 Runtime 实测**仍建议

## 三、实现约束与这一轮踩到的四个坑

### 3.1 逐帧 Clsn 只作用于紧邻一帧

判定帧之后还有 2 帧收招，第一版只在第 1 帧写了 `Clsn1: 0`，
第 2 帧可能把攻击框带回来。改成**判定帧之后每一帧都显式 `Clsn1: 0`**。

### 3.2 位移时长必须短于起手（第一版 265 / 267 实测 0 伤害）

最初让 `velSet` 持续整个 startup（8~9 tick），后撤系退了 40~52 px，
判定帧出现时人已经退出自己的框。改成**只在起手前 3~6 tick 短促冲刺/后撤**，
判定帧时早已停住。这与 1300 突进斩 / 1200 后撤投剑的「分段 velSet」惯例一致。

### 3.3 路由顺序：方向变体必须排在单键普通技之前

单键规则是 `command = "x" && command != "holddown"`，**不排除
`holdfwd` / `holdback`** —— 按 `→+A` 时 `command = "x"` 同样成立。
方向变体插在 ⑧ 单键之前才生效。

同时保留两条既有优先级（不是 bug，是 KOF 惯例）：

- ⑦ 闪身 `→/←+A+Z` 在前 ⇒ 组合键仍是闪身；
- ③ 投技 `贴身 →/← + S/X` 在前 ⇒ **极贴身时 →+S / →+X 出投技，不是升龙/冲回旋蹴**。
  拉开一点距离就是方向变体。`movelist.dat` 已写明。

### 3.4 全量验收的上下文污染 → 新增 `Move-Mid`

单独跑 8 条配方全 PASS，塞进全量 39 条后有 2 条 STATE-MISS：
上一条突进招把两人推到贴身，接着 `→+S` 被投技抢走。
`-Dist none` 让距离随上一条漂移，是测试装置的问题，不是游戏缺陷。

修法：`verify_moves.ps1` 新增 `Move-Mid 30 60` —— 中距既避开贴身投技
（`< 3/5`），又在判定框射程内（最远 84）。→ 系 4 招用 `mid`；
← 系 4 招是**近距反击**（后撤招框短，中距必然空振），用 `near`。

### 3.5 判定框直接复用，不要再缩放一次

`xscale = 0.48` 时 AIR 里写的是**素材坐标**（已预放大），引擎会自己乘 0.48。
新框照抄源 Action 的数值，所以 `frame_data.py` 的「框 vs 画面」8 招全 ok。
