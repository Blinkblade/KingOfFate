## 1. 核心游戏思路（一句话）

> **让每个人都能轻松放技能的格斗游戏：招式多、量大管饱、无搓招门槛；
> 策略深度来自「用自己的一整套招式，去反制对方可能放出的各种技能」。**

展开成三句：

| 原则 | 含义 | 由此产生的设计要求 |
| --- | --- | --- |
| **人人能放** | 不需要搓招（236/623/214…）。所有技能都是「方向 + 按钮」或「按钮 + 按钮」 | 输入层禁止出现需要精准输入的指令；一个新手按一次就能放出大部分技能 |
| **量大管饱** | 每个角色的技能数量要多（普通技 12 个起、大型技能 8 个以上） | 角色表按"技能条数"而非"连段深度"来扩张；美术产能优先供给动作种类 |
| **反制为纲** | 深度不来自搓招博弈，而来自**读对手的技能选择** | 招式之间必须有**可辨识的相性**（快/慢、飞行/跳跃、上/中/下、距离），且这些相性要能被玩家记住 |

**这与传统格斗游戏的差别**：传统格斗的深度来自"把三个指令打成一套连招"；
本作的深度来自"对手有 20 个招，我用我的 20 个招去拆解他的选择"。
因此：

- 我们的**取消/连段系统不是卖点**（但仍需存在，用于正常攻防）
- 我们的**单招设计质量与相性矩阵**才是核心资产
- 平衡的目标不是"谁的真确更高"，而是"谁的招式组合更难被针对"

## 2. 操作体系（2026-10-02 定版）

### 2.1 键位分工

| 键 | 角色 | 耗气 | 用途 |
| --- | --- | --- | --- |
| `A` | 轻拳 | ❌ | 普通招式第一档（站/蹲/空） |
| `S` | 重拳 | ❌ | 普通招式第二档 |
| `Z` | 轻脚 | ❌ | 普通招式第三档 |
| `X` | 重脚 | ❌ | 普通招式第四档 |
| `C` | **气键** | ✅ | 与方向或 A/S/Z/X 组合 → 中型技能 |
| `D` | **超气键** | ✅ | 与方向或 A/S/Z/X 组合 → 大型技能；`C+D` 同按 → 终极技 |
| `方向键` | 修饰 | — | `↓` 蹲、`↑` 跳、`→` 前、`←` 后（**不做 236/623 这类序列**） |
| `Enter` | — | — | START / 确认 |

**规则一句话**：

```text
只用 A/S/Z/X        → 不耗气的普通招式
带 C 或 D           → 消耗气的技能
```

这条规则本身就是教学成本的上限：**玩家学会一次，之后不需要再记指令表**。

### 2.2 为什么这么设计

1. **C/D 之前是空闲键**（引擎的 `c` / `z` 按钮在我们的四键体系里没有用途），
   不需要新增按键，也不需要改引擎键位。
2. **"带不带 C/D"是一个可以用肌肉记忆表达的判断**（我这一下要不要放气），
   比"搓什么招"快一个数量级。
3. **它天然分层**：普通招式负责日常攻防与消耗，气键负责破局与终结，
   玩家可以按"我现在要不要花气"来选择动作。

### 2.3 输入形态清单（全部为简单组合）

| 形态 | 示例 | 归类 |
| --- | --- | --- |
| 单键 | `A` | 普通（站姿第一档） |
| 方向 + 单键 | `↓A` / `→A` / `←S` | 普通（蹲/前/后变体） |
| 空中 + 单键 | 空中 `S` | 普通（跳跃攻击） |
| 气键 + 方向 | `↓C` / `→C` / `←D` | 中/大型技能 |
| 气键 + 普通键 | `C+A` / `D+S` | 中/大型技能 |
| 双气键 | `C+D` | 终极技（耗满气） |
| 方向 + 投技键 | `→A`（贴身） | 投技 |

**明确禁止**：任何形如 `↓↘→+A` 的序列指令；任何需要摇杆/搓键的输入。

## 3. 相性系统（深度从哪来）

深度不靠输入难度，就必须靠**可读的相性**。设计上，每个角色需要覆盖以下维度：

| 维度 | 取值 | 反制关系 |
| --- | --- | --- |
| 距离 | 近 / 中 / 远 | 远招式起手慢 → 近身可抢先；近招式够不到 → 需位移 |
| 高度 | 上段 / 中段 / 下段 | 下段可打蹲防；上段惩罚跳跃 |
| 反应速度 | 快（≤4 帧起手）/ 慢 | 快招先手压制；慢招可预读 |
| 飞行道具 | 有 / 无 | 跳跃、远程、防护类反制 |
| 破防 | 有 / 无 | 破防招是气键技能的主要职责 |
| 部位 | 头 / 胸 / 脚 | 与对手身高/姿态组合形成克制 |

**平衡检查表**（每个角色每版都过一遍）：

- [ ] 每个气键技能是否都有至少一个普通招式可以先手压制它？
- [ ] 每个普通招式是否至少被一个气键技能反制？
- [ ] 同一相性（距离/高度）下技能数量是否失衡？
- [ ] 终极技的出手机会是否被"防"类技能覆盖？

## 4. 角色内容产能（服务"量大管饱"）

一个角色的最低内容量：

| 类别 | 数量 | 说明 |
| --- | --- | --- |
| 普通招式 | **12**（站/蹲/空 × A/S/Z/X） | 基础，状态机固定 |
| 方向变体 | 4~8 | 前后方向带来的位移/性质变化 |
| 中型技能（`C` 系） | 4~6 | 耗气 300~600 |
| 大型技能（`D` 系） | 4~6 | 耗气 800~1200 |
| 终极技（`C+D`） | 1~2 | 耗满气 |
| 投技 | 2 | 前后各一 |

**美术成本是瓶颈**：每多一个技能就多一组动画。因此产能提升的优先级是：

1. **换更高精度、动作更全的美术源**（进行中，见 P6）
2. **动作条工具 + AI 辅助重绘**（`tools/anim_strip.py` 已在用）
3. 招式复用：同一套动画可服务不同技能（不同判定/不同消耗）

## 5. 技术方向（不变的部分）

战略转向**不改引擎、不改架构**：

- 引擎仍是 IKEMEN GO `v1.0.0-rc.5`（不重造）
- 角色仍是"骨架 + 美术 + 映射表"三层分离（`archer.sff` / `.air` / `asset_map.csv`）
- 工具链仍为只读 + 可复现（`tools/sffctl` `airtool` `sndctl` `sffpack` `validate_character`）
- **变的是**输入层（去掉搓招）与内容层（招式数量与相性）

**输入层改造工作量预估**：现有 `command.zss` 已是"命令名 → 状态号"的路由层，
把 MUGEN 的 `QCF_x` 之类换成 `SIMPLE_*` 形式的简单组合是**改命令定义 + 改路由顺序**，
不动状态机。预计每个角色半天。

## 7. 不变的东西（提醒别过度改动）

- 非商用同人素材的合规处理（见 `assets/LICENSE_MANIFEST.csv`）

- 一切变更都要有实测证据（工具 + 截图 + 状态读数）
- `game/` 是 Git 真值，`engine/ikemen-go/` 只作为运行时副本
