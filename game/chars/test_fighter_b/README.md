## 1. 玩法定位：它和 Fighter A 差在哪

Fighter A 是**贴上去打**的角色；Fighter B **保持距离、用投射物和长手控制空间**。

| | Fighter A（Rushdown） | **Fighter B（Zoner）** |
| --- | --- | --- |
| 走路速度 | 前进 2.4 / 后退 2.2 | **前进 2.1 / 后退 2.4**（更慢逼近、更快脱离） |
| 最强距离 | 贴身 ~20–60 px | **95 px 以外** |
| 主力手段 | 突进直拳 1000（位移 22 px） | **投射物 1000**（隔空开火） |
| 对空手段 | 1100 升龙踢（判定到 y=-131） | **1100 升龙上勾（判定到 y=-152）** + 410 对空 Normal |
| 最长普通技 | 站重脚 D 到 x=84 | **站重拳 C 到 x=105**（长手） |
| AI 末位行为 | `距离≥45 → 走向对手` | `距离<70 → 后跳` / `距离75–165 → 走位` |
| Super | 一记 200 伤害的重拳 | **3 连发气弹弹幕（195）** |

**两者都只用同一套体系**：同一套状态号约定、同一套 `CanChain` 取消链、同一个 `power` 气槽、同一套公共状态。
P4 要证明的正是"同一套架构能承载两种战斗风格"。

## 3. Projectile —— P4 的核心机制

### 3.1 它是什么

用 IKEMEN **原生 `projectile{}` 状态控制器**实现的真投射物（不是 Helper，也不是 Explod 假装的）。

- **注册处**：`engine/ikemen-go/src/compiler.go:98`（`"projectile": c.projectile`）
- **参数表**：`compiler_functions.go` 的 `projectileSub`
- **运行时实现**：`char.go` 的 `Projectile` 结构体 + `update()` / `tick()`

**为什么不用 Helper 方案**：引擎已经提供了完整能力（生成 / 速度 / 重力 / 生命周期 / 命中次数 /
优先级 / 与角色状态解耦），用 Helper 相当于在角色层手搓一个投射物系统 ——
那正是合同 §11.1 与 §29 明令避免的。

### 3.2 生命周期四道闸门（防"永久残留 / 数量失控"）

| # | 参数 | 值 | 作用 |
| --- | --- | --- | --- |
| ① | `projhits` | 1 | 命中一次即消失（防重复命中） |
| ② | `projremovetime` | 130 | 生成后 130 tick 强制消失（约 2.2 s） |
| ③ | `projedgebound` / `projstagebound` | 40 | 飞出边界 40 px 即消失 |
| ④ | `var(10)` 闩锁 | — | 每次状态执行**恰好生成 1 枚** |

④ 是必需的：`animElem = N` 在**第 N 个元素的整个持续时间内**都为真（不是只在第一帧），
所以 `if animElem = 4 { projectile{...} }` 会按元素时长（3 tick）重复生成 3 枚。
本角色的写法是 `if animElem = 4 && var(10) = 0 { var(10) := 1; projectile{...} }`。

### 3.3 ★ 最关键的一条：投射物的攻击框必须用 `Clsn1Default`

投射物动画（`.air` 的 **Action 1005**）结构是"一帧过渡 + 一帧 `-1` 保持"：

```
1000,4, 0,0, 4       ← 帧 1（4 tick）
1000,4, 0,0, -1      ← 帧 2，-1 = 无限保持
```

**用 `Clsn1: N` 逐帧声明时，攻击框只作用于紧邻的那一帧** —— 到 `-1` 保持帧就失效了，
于是投射物只在生成后的 **4 tick** 内带判定（那时它只飞了 24 px），
**视觉上是一个飞得很好看的哑弹**。

判断方法（P4 实测到的形状）：小判定框全都不命中，只有**超大**判定框才命中 ——
因为超大框的水平范围大到在生成的瞬间就够到对手。

**正确写法**：`Clsn1Default: N`（按定义就是"整个动画的默认框"，与 `Clsn2Default` 同一机制）。
改用之后投射物全程带判定，实测能把对手打到 K.O.。

### 3.4 与角色状态解耦

投射物生成后拥有自己的 `pos` / `velocity` / `anim`（`char.go` 的 `Projectile`）。
角色之后出招、收招、被打都不影响它 —— 见 Phase Report 的 Gate 7 组。

## 4. Anti-Air —— 对空能力

三件工具，各管一档：

| 工具 | 状态 | 判定框高度 | 起手 | 用途 |
| --- | --- | --- | --- | --- |
| 蹲重拳 C | 410 | 到 **y=-112** | 8 tick | 对手已经跳到很近时用（快） |
| 升龙上勾拳 | 1100 | 到 **y=-152** | 12 tick | 对手在较远/较高处时用（更高更远，带击倒） |
| 气弹（投射物） | 1000 | 世界 y ≈ -100…20 | 9 tick | 顺带能打到空中，但不是专门手段 |

**角色身高是 60** —— 所以 1100 的判定框高度是身高的 2.5 倍，几何上确实覆盖跳跃路线。

**几何是"向上"的，因此它不是万能技**：410 与 1100 的判定都集中在胸以上，
贴地的低姿目标打不到 —— 这是设计意图（合同 §10.2：Anti-Air 不该同时是万能的近身技）。

## 5. EX 与 Super

### EX（1010）相对普通版（1000）的强化 —— 三项，不是"换个状态号"

| | 1000 | 1010 |
| --- | --- | --- |
| 到发射 | 9 tick | **4 tick** |
| 发数 | 1 | **2**（AnimElem 3 / 5，高度差 18 px） |
| 合计伤害 | 60 | **110** |
| 速度 | 6 px/tick | 7.5 px/tick |
| 气耗 | 0 | **500** |

实测：`POW 580 → 80`（正好 500）。

### Super（3000）—— Zoner 的 Super 是"弹幕"

一次 **3 发**（AnimElem 4 / 7 / 9，t = 9 / 18 / 26），每发 65 伤害、速度 8，三发高度不同。
对手不能靠一次防御或一次跳跃躲掉全部。

实测：`POW 2000 → 1000`（正好 1000）。

## 6. Meter（气槽）

- 用引擎原生 `power`，**没有第二套资源**。
- `test_fighter_b.const` 的 `power = 2000` 是**上限**（不是起始值）。对局起点为 0，且**跨回合保留**。
- 收入：命中给气（≈0.7× 伤害）+ 状态头 `poweradd`；
  支出：路由层 `power >= N` 门 + 状态内 `powerAdd{value: -N}`。
- **检查在路由层（`command.zss`），扣除在状态里** —— 与 Fighter A 同一约定。

## 7. Cancel（取消链）

**沿用 P3 的等级系统，没有新建第二套**（`command.zss` 的 `CanChain(lv)` + 状态里 `AtkInit(lv)`）：

```
lv1 轻普通技（200/230/400/430/600/630）
  ↓
lv2 重普通技（210/240/410/440/610/640）
  ↓
lv3 必杀技（1000 投射物 / 1100 对空）
  ↓
lv4 EX（1010）/ Super（3000）
```

等级**只增不减** → 连段长度天然有上限（最长 4 段），不可能无限循环。

**取消不要求命中**（空挥也可取消）—— 沿用项目现有约定，P4 未改。

## 8. AI（`AI.zss`）

**规则 AI**（顺序 = 优先级），**不是** Utility AI（那属 P9）。

| # | 行为 | 条件 |
| --- | --- | --- |
| ① | 防御 | 对手正在攻击且在防御距离内 → 公共状态 120 |
| ② | **对空必杀 1100** | 对手在空中 + 25–160 |
| ③ | 对空 Normal 410 | 对手在空中 + 很近 |
| ④ | Super 3000 | power ≥ 1000 + 远距离 + 概率 |
| ⑤ | EX 1010 | power ≥ 500 + 中远距离 + 概率 |
| ⑥ | **投射物 1000** | **距离 ≥ 95** ★ Zoner 主力 |
| ⑦ | 长手牵制 210 | 距离 55–140 |
| ⑧ | 中距离普通技 | 240 / 230 / 440 |
| ⑨ | 近身普通技 | 200 / 430 |
| ⑩ | 投技 800 | 贴身 + 概率 |
| ⑪ | **后跳拉开 105** | 距离 < 70 ★ 与 Fighter A 的"接近"相反 |

**★ 本角色故意没有"走路兜底"规则**（Fighter A 有）：AI **不走命令系统**，
进入公共状态 20 之后走路方向由**引擎的默认 AI 方向（朝对手）**决定 ——
对 Zoner 是反效果（实测第一次 AI 对局两个角色贴在一起）。
所以"拉开"只用**有确定方向**的公共状态 105（后跳）表达。

## 9. 已知限制（不藏）

1. **占位素材**：`.sff` / `.snd` 是 KFM 的（CC-BY-NC，`prototype_only`，已登记 `assets/LICENSE_MANIFEST.csv`）。
   **发布前必须替换**。投射物精灵 1000,4 是一个**完整人形**，所以画面里像"一个人飞出去"。
2. **投射物判定框的尺寸是基于占位素材实测调出来的**（±40 × ±60），不是从美术尺寸推导。
   P5 换正式投射物素材后必须**重画**。
3. **Anti-Air 的"空中命中"交互未取得实测截图**：本机合成注入长期无法让对手起跳
   （根因已定位并修复，见 §10），修复后的剩余时间不足以重跑该组验证。
   现有几何依据是 `.air` 定义 + 角色身高对比。
4. **取消链缺少精确时间序证据**：已取得 `State 200 → State 1000` 的状态序列，
   但两次注入之间相隔约 55 帧，**未能证明转换发生在 200 的取消窗口内**（20 tick）。
5. 蹲攻 / 跳攻的起动帧数是从 `.air` 帧表推导的，未逐项做伤害实测
   （Fighter A 的 12 个普通技在 P3 已全测）。

```powershell

    -Phases '0x28:0.06,0x28+0x27:0.06,0x27:0.06,0x09:0.35' -SettleSec 0.02 -ShowDebug
```

**本机测试注意事项**（P4 新增 / 确认）：

- 注入按键前**必须把 `save/config.ini` 的 `[Keys_P1]` 改成 `x=TAB`**（字母键不可达），**测完还原**。
- **方向键是"扩展键"**：`inject_phases.ps1` 的 `Press-Key` 必须带 `KEYEVENTF_EXTENDEDKEY` 标志，
  否则引擎收到的是"小键盘 8"而不是"上"，角色不会跳（P4 已修复该脚本）。
- 调试覆盖层（`Ctrl+D`）是**开关**：harness 现在会**先检测再按键**，避免连按两次把它关掉（P4 已修复）。
- 前台焦点在无键盘活动的会话里**会间歇性拿不到**；harness 现在会按 ALT 释放前台锁并重试 3 次（P4 已修复）。
